## Summary for the author

Hi @dvaldes, thanks for picking up Chile. The intent is right: answering Austral quickly, deduplicating by `eventId` and keeping signature verification in its own class are the right building blocks, and the status mapping for the three documented event types is correct.

I can't approve it yet, because in this domain a wrong payment status changes a customer's coverage, and the plan is to switch off the nightly import for Chile right before the month-end peak. Five issues must be fixed before merge:

1. **A live webhook secret is committed** (`application.yml:19`). It needs to be rotated today, whatever happens to this PR.
2. **Requests without a signature header are accepted**, so anyone can post a `PAYMENT_CONFIRMED` and get a policy reinstated.
3. **We answer `200` before anything is stored durably, and processing errors are swallowed.** If Salesforce is down (about 97% available) or the pod restarts, a payment Austral considers delivered is lost for good.
4. **Out-of-order events can move a payment backwards.** A late `PAYMENT_CONFIRMED` after a `PAYMENT_REVERSED` reinstates a policy whose money was returned.
5. **Payer name, RUT and email are written to the logs.**

The tests need another pass too. Two of them pass with or without the code they claim to test, and one asserts the error-swallowing behavior. I've suggested concrete fixes per finding, and most map to patterns we already have in the target design: durable queue before `2xx`, upsert by `Payment_Key__c`, status precedence. Happy to pair on it.

## What looks good

- Answering Austral fast and processing asynchronously is the right instinct for a 10 s timeout and a slow Salesforce. It needs a durable queue behind it (#3).
- Using `eventId` for deduplication follows Austral's spec ("use `eventId` to detect replays").
- Signature verification lives in its own small class, which makes it easy to fix and test (#10).
- The mapping of the three documented event types to `Captured` / `Failed` / `Refunded` is correct.
- The PR description is clear about what was tested and what is left for later (the secret), which made this review much easier.
