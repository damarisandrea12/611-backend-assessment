# Assumptions

> The scenario is intentionally incomplete. Record every assumption you needed to make, and the part it affects.

| # | Assumption | Why I needed it | Part(s) affected |
|---|---|---|---|
| A-01 | Provider notifications carry no card data (only tokens), as stated in the scenario; the payment token value itself is not needed downstream and is dropped. | To decide what personal/sensitive data the canonical event may carry. | A, B |
| A-02 | A single Azure region serves the three countries (stated); no multi-region or geo-DR is required. Zone redundancy inside the region is used for production. | Sizing, availability and IaC. | A, C |
| A-03 | The API Manager can forward the request body **byte-for-byte** and all provider headers to the backend (no JSON re-formatting). | HMAC must be computed over the raw body. | A, B |
| A-04 | The API Manager authenticates to the Intake service with a machine-to-machine token from the IdP, and Intake ingress is private. Providers themselves cannot obtain IdP tokens, so webhook authenticity relies only on their HMAC signatures. | Trust boundary between API Manager and Azure. In Part B, the M2M token check is left to the platform and not implemented. | A, B, C |
| A-05 | Providers do not publish stable source IP ranges; an IP allow-list at the API Manager is optional, not relied on. | Webhook endpoint hardening. | A |
| A-06 | Quetzal sends a `Quetzal-Signature` header with exactly the documented format; header names are case-insensitive (HTTP). | Signature parsing. | B |
| A-07 | Quetzal `charge.refunded` maps to `REFUNDED` for **both total and partial** refunds (Salesforce has a single `Refunded` status); `refundedAmount` carries the refunded amount. Whether a partial refund should re-suspend a policy is a Salesforce-flow decision. | `Status__c` has no "partially refunded" value. | A, B |
| A-08 | A notification whose policy reference cannot be normalized to `POL-<CC>-<9 digits>` matching the provider's country is still **accepted** (it is an authentic, real payment), published with `policyNumber = null`, and parked for operations instead of being sent to Salesforce. Normalization rules: trim, upper-case, and prefix `POL-<CC>-` when the value is exactly 9 digits. | Andina 2.3 delivers the reference as typed by the payer (root cause of INC-0412). Rejecting would lose a real payment once retries are exhausted. | A, B, D |
| A-09 | Within one provider transaction, `CAPTURED` and `FAILED` are mutually exclusive (as documented in the lifecycles). If both are seen, the first one wins and the conflict is flagged as an anomaly. | Status precedence rule for FR5. | A |
| A-10 | Salesforce outages (~ 3% of the time) are spread through the month and have lengths spread between 5 and 90 min. If most outages are longer than 60 min, the 99.5%/1 h freshness target cannot be met by any integration design; freshness is then also reported excluding Salesforce-declared outages. | Capacity and NFR2 calculation. | A, D |
| A-11 | Retention: notification records 180 days, payment state 24 months after last change. No legal retention requirement was provided; since no personal data is stored outside Salesforce, these periods are driven by operations and chargeback windows. | Data design. | A, C |
| A-12 | Downstream consumers (Finance, Notifications) accept at-least-once, unordered delivery and use `idempotencyKey`, `status` and `statusChangedAt` to deduplicate and order. | Contract for FR6. | A, B |
| A-13 | Unknown event types (e.g. a new Quetzal `charge.*` type) are acknowledged with `200` and ignored with a metric; unknown **states inside known types** are rejected with `400` and alerted. | Avoid writing a wrong status by defaulting (e.g. "Pending"), while not causing endless retries for irrelevant events. | A, B |
| A-14 | For Andina, the timestamp tolerance is **10 minutes** (provider recommendation); for Quetzal it is **300 seconds** (provider requirement). Clock skew of Meridian servers is negligible (NTP). | Replay protection. | B |
| A-16 | Quetzal's `statusChangedAt` is taken from `refunded_at` for refunds, `paid_at` for captures, and from `created` when those are null (e.g. failed charges). | Quetzal has no single "state change time" field. | A, B |
| A-17 | Monthly cost estimates use Azure public list prices (pay-as-you-go, USD, 2025-2026 order of magnitude) and exclude the existing platform services (Log Analytics workspace, API Manager, IdP). | Cost estimate in `AZURE_SERVICES.md`. | C |
| A-18 | The repository is hosted on GitHub; CI/CD uses GitHub Actions with OIDC federation to Entra ID (workload identity federation) and GitHub Environments with required reviewers for `test` and `prod`. | Pipeline design. | C |
| A-19 | The on-call rotation of the Payments Integration squad is paged through Azure Monitor action groups (e.g. to the squad's paging tool); the Salesforce team has its own channel for Salesforce-side issues. | Alert routing. | D |
| A-20 | During INC-0412, "Payments upserted in Salesforce" counts successful upserts (including updates of existing records), so it is not exactly the number of unique payments. | Interpreting the incident numbers. | D |
| A-21 | Webhook request bodies are at most 64 KB; larger bodies are rejected by the API Manager and by Intake with `413`. | Basic abuse protection. | B, C |
| A-22 | An Andina `REVERSADA` reverses the **full** transaction amount (the spec has no partial-reversal field), so `refundedAmount = valor`. | Canonical `refundedAmount` for Andina. | B |
| A-24 | A container registry is needed for the images; I create one per environment in IaC. If the platform already provides a shared registry, the module is replaced by an `existing` reference. | IaC completeness. | C |
| A-25 | The integration platform's API Manager can reach a private Azure VNet (VNet integration, peering or Private Link). The Container Apps environment in test/prod is internal (no public IP). | Trust boundary 2 → 3 and IaC networking. | A, C |
